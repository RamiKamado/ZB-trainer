# ZBLL / ZBLS 手順練習ツール

ZBLL 480 ケース・ZBLS 299 ケースのスクランブルを出題し、タイマーで練習するためのツールです。
`index.html` 1 ファイルで完結していて、外部の CDN もサーバーも使いません。ダウンロードして
ブラウザで開くだけでも、GitHub Pages に置いてもそのまま動きます。ホーム画面に追加すれば
独立したアプリのように全画面で開きます（アイコンと manifest を同梱しています）。

## 公開のしかた（GitHub Pages）

1. このリポジトリを GitHub に push します。
2. リポジトリの **Settings → Pages** を開きます。
3. **Source** を `Deploy from a branch`、ブランチを `main`、フォルダを `/ (root)` にして保存します。
   （`index.html` のほか `manifest.webmanifest`・`apple-touch-icon.png`・`icon-192.png`・`icon-512.png`
   も同じ場所に置いてください）
4. 数十秒後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます。

`index.html` をリポジトリ直下に置いているので、追加の設定やビルドは不要です。

## ホーム画面に追加（iPhone / Android）

GitHub Pages などに公開したうえで開くと、ホーム画面に追加して独立したアプリのように使えます。

- **iPhone / iPad** — Safari で開き、共有ボタン → 「ホーム画面に追加」。追加したアイコンから起動すると
  Safari の上下ツールバーが出ず、全画面で開きます。
- **Android** — Chrome で開き、メニュー → 「アプリをインストール」または「ホーム画面に追加」。

`index.html` をローカルのファイルとして開いた場合はホーム画面追加の対象にならないので、
公開した URL から開いてください。アイコンと `manifest.webmanifest` は `index.html` と
同じフォルダに置いたままにしてください。

## 使い方

### ケース選択画面

- **プリセット** — 選択中のケースに名前を付けて保存し、あとから読込・追加・上書き・削除ができます。
- **ZBLS** — オンにすると ZBLS から練習できます。FR / BR / FL スロットを複数選択でき、
  ケースは参照元の F2L 番号ごとにまとまっています。「手順を編集」で自分の手順に差し替えられます
  （ケースのボタンを右クリック／長押しでも開きます）。
- **ZBLL** — 7 つの OLL グループ × CP サブセット × 12 ケース。グループ単位・サブセット単位の一括選択があります。

選択内容・プリセット・自作手順はブラウザのローカル保存に入るので、次に開いたときも残ります。

### 統計画面

ケース選択画面の「統計」から開きます。練習したタイムはケースごとに自動で蓄積されます。

- 総ソルブ数・合計時間・全体平均・ベスト・ワースト・練習済みケース数
- ZBLL をグループ → CP サブグループ → 個別ケースの順にたどれる平均タイム一覧
- 平均が遅いケース 上位 10
- ZBLS を F2L ケースごとにまとめた平均タイム一覧

タイムの色は 0 秒で緑、5 秒で黄、10 秒以上で赤になります。横のバーも同じ色です。
「記録を消去」で蓄積をリセットできます。

### 練習画面

- **Straight** 選択順 / **Random** 重複ありランダム / **Recap** 1 回ずつランダム の 3 モード。
- タイマーはスペースキー長押し、またはタイマー部分を長押しして離すとスタート、もう一度でストップ。
- 集計は回数・直前・ベスト・ワースト・平均・ao5・ao12 と記録一覧。
- 下部に直前のケース、そのスクランブル、想定していた ZBLS 手順が出ます。
  「★ 追加」でその場で苦手ケースを登録、「✕ 削除」で登録済みのケースを外せます（キーボードは P / D）。
  プリセットを読み込んで練習を始めた場合は、その読み込んだプリセットが追加・削除の対象になります。

### スクランブルについて

実際のソルブと同じ順番になるよう、**AUF → ZBLS → AUF → ZBLL → AUF** の逆順・逆向きを
1 本に詰めたものを出題しています。AUF は 3 か所それぞれ「なし / U / U2 / U'」からランダムです。
ZBLS をオフにしたときは **AUF → ZBLL → AUF** の 2 か所になります。

ZBLS は「エッジを揃えて最終スロットを埋める」という条件しか課さないため、使う手順が違えば
出てくる ZBLL ケースも変わります。画面に表示される ZBLS 手順を使えば、選んだ ZBLL ケースが必ず出ます。

## 検証について

スクランブルと手順はすべて、キューブのシミュレータで実際に回して確認したものです。

- ZBLL スクランブル 2,840 本 — 図の状態と完全一致
- ZBLS 手順 299 ケース × 3 スロット — スロットが崩れること・手順で必ず解けること
- 出題されたスクランブル — スロットが崩れ、AUF + ZBLS 手順で F2L 完成とエッジ揃いになり、
  その結果の LL が選んだ ZBLL ケース（前後 AUF の 16 通りのいずれか）と一致すること

自作手順を登録するときも、ブラウザ側で同じ検証を通してから保存します。解けない手順は登録できません。

## データの出どころ

- ZBLL のケース図とスクランブル — [Roman-/zbll](https://github.com/Roman-/zbll)（ZBLL Trainer）のデータをもとに、
  向きを正規化して再検証したもの。
- ZBLS の手順 — 手持ちのスプレッドシートから抽出し、全件検証したもの。
- F2L の番号 — [SpeedCubingTips.eu の ZBLS ページ](https://www.speedcubingtips.eu/zbls-zborowski-bruchem-last-slot/)（42 ケース）に合わせています。
- ケースの図 — VisualCube と同じポリゴン座標で描画しています（画像は外部から読み込まず、SVG を埋め込み）。

公開する前に、各データの利用条件をご自身で確認してください。手順そのものの権利関係は出どころによって異なります。

## 動作環境

モダンなブラウザであれば動きます。外部通信は一切行いません（ケース図をクリックしたときに
VisualCube のページを開くリンクだけ外部です）。記録はページを閉じるとリセットされ、
選択内容・プリセット・自作手順のみ保存されます。
